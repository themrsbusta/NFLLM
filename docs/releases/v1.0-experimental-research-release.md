# NFLLM 1.0 Experimental Research Release

This is an experimental NF-DOS inference prototype for a documented subset of GGUF v3 models using the `llama` architecture. It is not a port of the full upstream `llama.cpp` runtime.

## Assets

- `NFLLM-1.0-Experimental-Research-Release-DOS.zip`: DOS executable and research build artifacts, static plugin libraries, manifests, license and usage notes.
- `NFLLM-1.0-Experimental-Research-Release-Source.zip`: source, build scripts, documentation and the separately labeled upstream reference source.
- Each ZIP has a `.sha256` sidecar.

Neither ZIP includes model weights, DOS disk images, or DOS/4GW. The main executable requires DOS/4GW or a compatible extender. Obtain a compatible GGUF model separately and review its license; see the [v1.0 model guidance](https://github.com/themrsbusta/NFLLM/blob/v1.0/models/README.md).

## Research scope

The baseline is 386+x87 in NF-DOS 5.01.3314 with DOS/4GW 1.97, tested in the supplied evidence on 86Box 6.0 with an AMD Am486DX4 profile at 100 MHz and 96 MiB. The source includes F32, Q8_0, Q4_0, Q2_0, Q2_K, IQ3_XXS and IQ3_S decoding, plus experimental 3DNow!, MMX and SSE2 kernels.

3DNow!, MMX, SSE2 and generic-486 results are QEMU ISA-proxy experiments. No physical Geode or Atom hardware was tested. The SSE2 run used an isolated N270 guest with `CR4.OSFXSR` enabled; general DOS/DPMI XMM-state safety remains unverified. Standalone MS-DOS was not validated. The EFLAGS.ID probe under DOS/4GW was inconclusive and did not execute CPUID.

The upstream reference snapshot was kept under `source/upstream-llama.cpp/` at commit `b79696f1f556cb30b0c184838115007d929baca8`; it remains available in the [v1.0 source tag](https://github.com/themrsbusta/NFLLM/tree/v1.0/source/upstream-llama.cpp). NFLLM is not represented as a complete port, fork, or wholly independent reimplementation. A file-level source-reuse audit remains pending.

## Verification note

The supplied research archive passed its SHA-256 check and ZIP integrity test. Its bundled evidence reports the documented guest and proxy checks as passing. The publishing environment did not have Open Watcom or 86Box installed, so I did not reproduce the DOS build or guest runs here. The release build artifacts are taken from the checksum-verified supplied snapshot.
